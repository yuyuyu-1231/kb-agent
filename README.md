# kb-agent

企业知识库问答 Agent：**自研 mini harness 内核 + 检索增强 + 低置信度转工单**。

> **在线演示**：<http://47.93.237.92:8000>
> 访问口令见简历 / 私信（公网服务必须鉴权，否则背后的 LLM key 会被人刷）

---

## 它能做什么

- **知识库问答**：检索 → 带引用的回答，答案里的 `[n]` 和引用卡片可双向跳转
- **流式输出**：SSE 逐 token 推送，不是「跑完再切片」
- **多轮会话**：`session_id` 维度的上下文；刷新页面能恢复上一轮对话
- **该转单就转单**：检索置信度不足时，如实说明并创建工单，而不是编一个答案
- **轨迹可回放**：每次运行落一份 trace，工具调用、裁剪、熔断都有记录

## 架构

```
app/api        HTTP 层：协议转换（SSE、表单、鉴权中间件）
app/services   业务层：检索、入库、工单
app/infra      适配层：LLM（OpenAI 兼容）、Qdrant、fastembed
harness/       内核层：ReAct 循环 / 工具注册 / 上下文裁剪 / 熔断 / 记忆 / 轨迹
```

**依赖方向是单向的**：`harness/` 不 import `app/`，换业务不换内核。

## 本地跑起来

```bash
cp .env.example .env      # 填 LLM_API_KEY
docker compose up -d --build
open http://localhost:8000
```

首次启动会自动把 `data/corpus/` 下的 PDF 入库（幂等，已有数据就跳过）。

## 几个实现上的取舍

| 决策 | 为什么 |
|---|---|
| 工具参数 → JSON Schema 由**函数签名自动生成** | 加工具只写函数，不改 schema |
| `run()` 是 `run_stream()` 的**收集器** | 线上跑流式，测试必须覆盖同一条代码路径 |
| 断连收口放 `finally` + `shield` | 用户关页面时 trace 和会话记忆仍要落盘 |
| 访问控制用**纯 ASGI 中间件** | `BaseHTTPMiddleware` 会缓冲响应体，SSE 会退化成「攒完再发」 |

## 评估

三份独立数据集（`data/eval_*.jsonl`），四层指标：

| 集 | 条数 | 关注点 |
|---|---|---|
| 主集 | 50 | 动作选择 / 关键点覆盖 / 引用准确 / 幻觉 / 应拒答 |
| 鲁棒性 | 45 | 口语化、模糊指代、错别字、多意图 |
| 安全 | 6 | 提示注入、越权索取 |

> 50 条样本的单项指标方差可达 ±5~20 点，所以 A/B 对比必须跑多次取平均 ——
> 这条结论本身就是评估过程里踩出来的。
