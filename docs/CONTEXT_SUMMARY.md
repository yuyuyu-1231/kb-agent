### 1.2 技术栈（以 `requirements.txt` 与代码 import 为准）

| 层 | 选型 |
|---|---|
| Web | FastAPI + Uvicorn + Pydantic |
| LLM | `openai` SDK，`base_url` 指向 DeepSeek |
| 嵌入 | `fastembed`，模型 `BAAI/bge-small-zh-v1.5`（onnxruntime，无 torch） |
| 向量库 | Qdrant（Docker） |
| PDF 解析 | **PyMuPDF**（`app/services/ingest.py` 中 `import pymupdf`） |
| 存储 | SQLite（会话记忆 `harness/memory.py`、工单 `app/services/ticket.py`） |
| 前端 | 原生 HTML/JS 单文件，`fetch + ReadableStream` 手工解析 SSE |
| 部署 | Docker Compose（app + qdrant） |
| 测试 | pytest + pytest-asyncio |

**技术栈更正**：早期项目记忆与交接文档写过"MarkItDown 解析 PDF"，与当前代码不符。`requirements.txt` 中 markitdown 被标为 deferred（理由：不提供页码、会引入 magika），实际解析走 PyMuPDF。后续生成任何文档以 **PyMuPDF** 为准。

### 1.3 架构

五层，依赖单向（上层依赖下层，内核层不反向依赖应用层）：

```
L0 harness/         内核层：Agent 运行时，零 import app
L1 app/api/         HTTP 层：协议转换、SSE、鉴权中间件
L2 app/tools/       工具层：模型契约翻译（schema、参数）
L3 app/services/    业务层：检索、入库、工单、评估
L4 app/infra/       适配层：LLM、Qdrant、Embedding
```

harness 六个模块及职责：

| 模块 | 职责 |
|---|---|
| `loop.py` | ReAct 主循环、引用编号注册表；`run()` 是 `run_stream()` 的收集器 |
| `tools.py` | 函数签名 → JSON Schema；参数校验失败回喂模型 |
| `context.py` | 四级上下文裁剪（截断 → 丢检索 → 滑窗 → 兜底） |
| `guard.py` | 三重熔断（轮数 / token 预算 / 重复动作指纹） |
| `memory.py` | 会话记忆（SQLite） |
| `trace.py` | 轨迹 JSONL + 内容寻址 artifact |

### 1.4 核心链路

`POST /documents/upload`（PDF → 解析 → 分块 → 嵌入 → Qdrant，按内容哈希幂等）
→ `POST /qa/ask` 或 `POST /qa/ask/stream`（检索 → 带引用回答 → 置信度不足时建工单）
→ `GET /qa/session/{id}`（刷新页面恢复会话）
→ `GET /health`（含 degraded 状态）

## 三、已确认的结论与决策

### 结论 1：这一轮不需要做第二个项目

依据（来自 `E:\JobHunt\reports\2026-11-06-agent-jd-scan.md`，2026-11-06 的北京 Agent/AI 应用方向实习 JD 扫描报告，样本 12 条）：

1. 技术命中率：Agent 90%、RAG 70%、评测 30%，三项均已覆盖且属深度覆盖。
2. 明确写实习时长的 6 条岗位全部要求 ≥3 个月，寒假 6-8 周 **0 命中**。
3. 按"寒假 6-8 周 + 大二 + 本科"三条件同时筛，样本内符合岗位 **0 条**。
4. 真正的瓶颈是可实习时长、届别、面试表达，不是项目数量；补第二个项目无法改变其中任何一项。

### 结论 2：把时间投向后端工程纵深（20-25 小时）

缺口：项目当前无任何 MySQL / Redis 代码（全库检索 `mysql` / `redis` / `psycopg` 无命中），存储为 SQLite + 进程内存限流。

拟补范围（尚未实施）：

1. 会话历史迁移 MySQL：`sessions` / `messages` / `traces` 三表 + 索引 + 事务。
2. Redis：检索结果缓存（key 含语料版本 + query hash，TTL 10 分钟）+ 工单创建幂等键。
3. 并发与可靠性：worker 模型、限流状态跨进程。

可复用资产：`app/models/schemas.py`（现成字段清单）、`harness/loop.py` 的 `stop_reason` 枚举（现成状态定义）、`data/eval_set.jsonl`（现成演示/压测语料）。

### 结论 3：第二个项目的启动窗口

- 最早窗口：2027 年 3-6 月；若寒假拿到实习，优先级降到最低。
- 候选选题（按推荐度）：A 持久化执行引擎（MySQL + Redis + checkpoint 续跑）；B 手写 MCP 协议层（JSON-RPC + stdio + 能力协商）；C LLM 网关（语义缓存 + 成本可观测）。
- 明确不做：多 Agent 协作框架、用 LangGraph 搭的系统、微调项目、知识图谱。

### 结论 4：简历能写 9 条 bullet，成色不均

| 成色 | 条数 | 对应内容 |
|---|---|---|
| 硬货 | 6 | ① harness 六模块运行时；② 工具 schema 自动生成 + 调用配对 + 熔断占位；③ 评估体系 151 条 / 四层指标；④ 数据驱动优化 76%→98%；⑤ 评估方法论（方差、批次、自证偏差）；⑥ 断连收口 + 12 轮长对话 |
| 需压缩 | 2 | ⑦ RAG 链路（可压到半行）；⑨ 前端 + 部署（可压成半行） |
| 需改写 | 1 | ⑧ 安全 + 鉴权（内容正确但偏长） |

第 9 条成色最弱，最接近"凑数"。

### 结论 5：三个数字表述隐患（处理方式是改讲稿，不改代码）

| # | 隐患 | 事实 | 处理方向 |
|---|---|---|---|
| 1 | 同一指标有两个数 | 应拒答 86.7%（原始运行 `data/reports/20261112-1543-main.md`）vs 100%（`docs/BASELINE.md` 重算）；幻觉 8 vs 2 | 简历用重算值，面试必须主动说明"重算过、判定脚本迭代三次" |
| 2 | P95 超标 | 9819 ms vs 自定目标 8000 ms；长尾来自应拒答题（4.07 步、8231 ms） | 简历写 P50 4410 ms，不单列 P95 |
| 3 | 数字过于完美 | Recall 100% / 引用 100% / 误拒 0% / 幻觉 2 条并列 | 主动加入非满分指标：MRR 0.892、关键点 89.4%、应拒答动作准确率 73.3% |

### 结论 6：简历写法约束

- 不写代码总行数（4250），改写模块数与架构约束（6 模块、内核零业务依赖）。
- 技能行补一句"手写等价于 LangChain AgentExecutor 的实现"，覆盖框架关键词的机筛，且与事实相符。

| 三重熔断 | Guard 能否拦住（用剧本化假模型构造异常） | 真实模型下这些异常的发生概率；`repeat_threshold=2` 是否误杀 |
| 间接注入 | 1 种载荷（HTML 注释 + 索要凭据话术），模型未泄露且主动预警 | 多段拆分的载荷、伪装成"温馨提示"的载荷、不含禁用词的表达 |
| 长对话 | 12 轮、6000 预算下裁剪与截断全触发 | 更长对话（>20 轮）、真实 30000 预算下触发裁剪的场景 |
| 安全集 | 6 条直接攻击 | 越权、多轮诱导、工具滥用 |
| 并发 | 无 | `memory.append` 读-改-写在多 worker 下会丢更新（代码注释已承认）；限流状态在进程内存，多 worker 时额度 = 配置 × worker 数 |
| 性能 | 单请求 P50 / P95 | QPS 上限、并发退化曲线、检索链路单独延迟 |
| 工单状态流转 | 建单、查单 | `ticket.update_status()` 未单独验证 |

### 5.3 部署与运维

| # | 事项 | 说明 |
|---|---|---|
| 1 | 公网口令是公开的（`kb-demo-2027`） | 这是演示取舍，不是产品级鉴权；真实产品需用户体系 + Redis 限流 + 按用户配额 |
| 2 | 本地 Docker Desktop（WSL 后端）反复退出 | 与镜像构建无关（服务器上三次构建均成功）；排查时不要把两者混为一谈 |
| 3 | Linux 上 `data/` 目录属主 | 容器以 uid 10001 运行，宿主机 bind mount 保留属主，需 `chown -R 10001:10001`；Docker Desktop 会自动放开权限，所以本机碰不到 |
| 4 | 对外暴露方式 | 直接暴露 IP + 端口，无 HTTPS；长期对外需补反向代理与证书 |
